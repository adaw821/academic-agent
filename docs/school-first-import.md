# AI 发现并首次导入学校课程（2026-10-28）

继续使用 `use_school_tools=true` 与 `allow_school_sync=true`，无需新增权限开关或数据库迁移。
前端在研究工作台开启“学校助手”和“允许同步课程”，即可说“帮我同步 Software Engineering 课程”。
需要当前账号先配置有效学校会话；无需事先在学校事务页面导入该课程。

## 匹配与执行

`sync_school_course` 优先按当前用户的本地课程匹配：名称不区分大小写，先精确匹配，再字面包含匹配。
单个英文词按词边界匹配，防止 `SE` 命中 `Database` 中间的字母而绕过别名识别。
字面匹配无结果时，让模型结合当前账号的实际课程列表识别缩写和中英文别名，例如 dbms、数据库。
模型只能返回候选列表的序号，不能指定 URL 或编造课程编号；序号越界、类型错误、调用失败均不执行语义目标同步。
本地唯一且明确的匹配继续复用原刷新接口；本地多门匹配或模型不确定时返回本地课程 ID 供确认。
明确指定本地 `course_id` 时仍只查询本地，不把其他账号或不存在的 ID 当成学校编号。
已存在但没有学校来源的本地课表课程，仍要求先关联来源，不自动把它与猜测的学校课程合并。

名称在本地未找到时，使用当前用户的学校会话发现课程，并按相同的精确优先规则匹配：

- 发现完整且唯一匹配：复用首次导入接口，采集并事务写入课程、作业与资源。
- 重名或多门匹配：不写入，返回最多 10 个候选及学校课程编号。
- 字面匹配无结果：结合实际发现列表进行模型别名匹配；唯一且明确时导入，多门或不确定则返回候选。
- 最终没有匹配：返回当前可见候选，供用户确认正式名称。
- 发现列表不完整：仅凭名称不自动认定唯一，也不宣称学校不存在该课程。

选择候选可回复“同步学校课程编号 22222”。模型用 `external_course_id="22222"`，与本地整数 `course_id` 分开。
也支持“Software Engineering（学校课程编号：22222）这个”：本轮明确标记的学校编号优先，
修正模型误放到本地编号字段或同时附带名称的情况；仍保留额外字段拒绝和同步权限检查。
学校编号兼容 JSON 整数与字符串，拒绝布尔、浮点、非正数；名称与学校编号同传时名称只作标签。
模型别名匹配仅接收课程名称，不接收学校会话或来源 URL。同名记录会补齐，不能因模型漏选而误判唯一；
候选超过 200 项或名称文本超过 12,000 字符时不截断后自动同步，改为请求用户给出更明确的名称或编号。
服务端会再次访问当前用户的学校课程发现结果；只有选定编号仍在可见列表中，才允许采集。
即使发现其他课程不完整，已明确选择且重新验证可见的唯一学校编号仍可同步，并返回完整性提示。

模型无法指定用户 ID、任意 URL 或批量课程。导入 URL 只能来自重新发现并校验的学校结果；
发现编号须与规范 URL 中的编号一致，采集快照来源也须与请求课程一致。
所有写入沿用用户锁和 `(user_id, source_url)` 去重，不会借用其他账号的本地课程。

## 回答与恢复

工具结果直接生成同步回答，不进行第二次模型推理来判断是否成功。
成功返回本地课程 ID、名称、作业/资源数量、完成时间和警告；不会声称附件已下载或进入知识库。
学校会话失效返回 409 `school_login_required`，学校访问失败返回 502，失败不报告同步成功。

`/ask/jobs` 保留同步结果检查点。写入成功后保存消息失败，普通重试复用结果；
写入成功但检查点尚未落盘时进程中断，可能再次采集，但仍按来源更新同一课程。
`restart=true` 会重新执行操作，不承诺外部采集恰好执行一次。
