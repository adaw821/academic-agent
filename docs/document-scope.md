# 问答文档范围

项目 ID 沿用 URL 参数，文档 ID 由前端选择后放入请求体；不从问题中的文件名、书名号或模型判断推断范围。

```http
POST /projects/1/ask
Content-Type: application/json

{"query": "这两份资料有什么区别？", "doc_ids": [11, 12], "candidate_k_percentage": 0.4}
```

以上路径为路由相对路径，部署时沿用现有 API 前缀和登录 Cookie。

`candidate_k_percentage` 使用当前请求字段名，类型为浮点数，范围为 `0 < 比例 <= 1`，默认 0.4。
例如当前范围有 250 个子片，传 0.2 时，两路召回各最多取 50 个子片；默认取 40%，传 1 时取全部候选。
数量按 `ceil(范围内子片总数 × candidate_k_percentage)` 计算，范围为空时返回空。
BM25 仍只返回词项匹配的子片，实际数量可以不足；两路融合去重后的数量不是固定百分比。
这个参数不控制最终 Prompt 的数量，后续重排过滤保持原逻辑。
客户端应发送当前比例字段，不再使用原来的固定条数字段 `candidate_k`。

- 不传 `doc_ids` 或传 `null`：检索当前项目中处理完成的文档，兼容旧请求。
- 传非空列表：仅检索选中的文档，向量和 BM25 均在数据库查询时限制范围。
- ID 必须是正整数；空列表、字符串 ID、布尔值等返回 422。重复 ID 自动去重。
- 任意 ID 不存在或不属于 URL 中的项目：返回 404，拒绝整个请求，不忽略无效 ID、不扩大范围。
- 任意指定文档未处理完成：返回 409，前端应检查文档状态。
- 项目不存在返回 404，无项目权限返回 403；先检查项目权限，再校验文档。
- 指定范围内没有召回结果时，沿用现有资料不足响应，不回退到整个项目。

前端可沿用项目文档列表接口获得真实 ID。取消全部文档选择并希望查询整个项目时，省略 `doc_ids`；不要发送空数组。

验证命令：`agent/Scripts/python.exe tests/test_document_scope.py`。测试使用临时 SQLite 和模拟模型服务，不访问业务数据库或外部模型。向量查询的范围条件通过 PostgreSQL SQL 编译检查，实际向量执行仍需 PostgreSQL/pgvector 环境联调。
