# 注册与学校自动连接

新注册必填应用账号资料、邮箱验证码、学生账号与学校密码。应用密码只保存哈希；学校账密、浏览器状态和会话使用 AES-256-GCM 加密，密文绑定本地用户 ID。学校凭据不进入模型、聊天、日志或后台任务参数。用户接口没有读取密码的功能。

## 配置

1. 安装 requirements.txt，并安装 Playwright Chromium；Windows 默认使用已安装的 Edge。
2. Windows 可运行 `./scripts/setup_school_key.ps1`，在仓库外生成仅当前服务账号可读取的密钥，并配置 `.env`。其他环境创建内容为 32 字节随机值 Base64 编码的私有文件，并填写 `SCHOOL_KEY_FILE` 的绝对路径。禁止把密钥放进仓库或数据库备份；密钥必须稳定，另行安全备份。更换密钥前需要迁移旧密文，直接替换会使旧凭据无法解密。
3. 执行 `python -m alembic upgrade head`，重启后端。生产环境使用 HTTPS；应禁止反向代理记录请求正文。线上密钥应由部署环境的密钥管理服务提供。

学校公开认证表单已观察到：SSO 的 `userName/password` 和 MIS 的 `j_username/j_password`。后台隐藏浏览器使用学校页面自身的密码加密逻辑，并仅允许列出的学校 HTTPS 主机。遇到 HTTP GET 跳转时升级为 HTTPS；不向 HTTP 提交账密，也不降级证书校验。验证码、扫码和二次验证当前只返回明确提示，不提供绕过或内嵌挑战交互；实际学校账号仍需端到端验证。

## 注册和同步语义

注册先检查邮箱验证码，再释放数据库锁进行学校认证，最后重新验证并原子消费验证码、创建用户与保存加密凭据。认证失败不创建账号、不消费有效验证码。每个学校账号及请求来源有限次认证额度。

注册成功后，进程内后台任务同步 ispace 当前进行中的课程、作业与资源索引，并使用 MIS 默认选中的学期直接解析课程明细。MIS 无头浏览器复用加密保存的状态，不截图、不 OCR。没有可靠教学日历时只保存学期名称，不猜测开学日期或教学周。无法确定时间/教室对应关系时整份课表导入失败，旧记录保留。重复导入去重；目前为追加模式，学校改动/取消的旧时段需人工核对删除。

后台任务只接收用户 ID。数据库保存 queued/running/completed/partial/failed/authentication_required 状态；进程重启可能中断任务，用户可在学校事务点击重试，已有数据保留。当前不承诺持久化任务队列或全用户定时调度。操作使用同用户跨进程文件锁；同步期间更新/删除连接返回 409，避免已删除凭据被后台重新写回。

后续读取学校会话前验证其有效性；过期时仅尝试一次密码认证，认证未完成后停止自动重试，要求用户更新账密。MIS 独立失效时也只尝试一次重连。网络故障不当成密码错误。

## 接口

- `POST /user/create`：新增必填 `school_account`、`school_password`。返回仍只有应用用户资料。
- `GET /school/account`：只返回 connected/state/message。
- `PUT /school/account`：验证并更新学校账密，成功后重新同步。
- `DELETE /school/account`：清除加密凭据与会话，保留已导入数据。
- `POST /school/account/sync`：请求重试同步；认证失败状态必须先更新账密。

老账号不做迁移或绑定引导。旧数据未自动清理；重测前单独确认清理范围。旧桌面连接 API 保留供原有工具使用，新注册用户的主要界面使用后台连接。
